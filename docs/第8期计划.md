# 第 8 期计划 · 告警增强 + 视图深化

> 2026-07-28 定稿。接第 7 期（监控对象扩展）。本期补北塔 BTSO/MC 的告警差异化能力与两种标志性视图。

## M1 动态基线告警

- 规则比较符加 `baseline_dev`：当前值 vs metrics_5m 中同设备同指标近 7 天同时段（±30min 窗口）均值，偏离超 N 倍标准差触发；阈值字段存 N
- 引擎 evaluate 时基线查询走 cagg（SQLite 无 cagg 回退原始表聚合，照报表的双方言模式）；结果按 (设备, 指标, 小时) 本批内存缓存，防 O(N²)
- 样本不足（如 <10 个点）不触发——新设备/新指标不会乱报
- 前端规则表单加比较符选项与说明；内置规则不加基线类（现场按需自建）

## M2 告警时刻指标快照

- 引擎 `_fire` 时抓该设备 metrics 最新值全集（照 metrics/latest API 口径）存事件详情（AlertEvent 加 snapshot JSON 列或复用现有字段，看现状最小改动；dev 库手工 ALTER）
- 前端事件详情/抽屉展示快照表（指标中文名 + 值 + labels）
- 快照查询失败静默（不阻塞告警）

## M3 规则模板批量套用

- `rule_templates` 表：名称/描述 + 规则定义（指标/比较符/阈值/去抖/等级）+ 设备选择器（同规则的三件套）
- API：模板 CRUD + `POST /api/alert/templates/{id}/instantiate`（按选择器展开设备分组一键生成规则，已存在同名跳过）
- 内置模板播种：照内置规则把现有 20+ 条翻成模板（按设备类型分组）
- 前端规则页加「从模板批量创建」入口

## M4 子网/机房分组子拓扑

- devices 加 `group_name`（字符串，空=未分组；dev 库手工 ALTER）；设备表单加输入框（datalist 提示已有分组）
- graph API 支持 `?group=` 过滤（节点+两端都在组内的链路）；布局按分组独立保存（layout API 加 group 维度，看现状 topo_links/pos 存储方式选最小改动）
- 前端拓扑页：分组切换下拉/breadcrumb（全部 → 各分组），进入分组只画该组节点

## M5 宿主机-数据库总线视图

- 利用 (ip,type) 同机多对象：`/bus` 视图——server_linux/server_windows 横向总线卡片，上方挂同 IP 的 database/application 对象；状态环（绿/橙/红=该对象最高 firing 告警等级）+ 告警角标数字（参照北塔截图二）
- API：`GET /api/bus` 返回主机+挂载对象+各对象状态聚合（复用 alert summary 口径）
- 纯展示页，无编辑；点击对象跳设备详情

## M6 零星项

- 监控循环读/写合并批量 SQL（2000 台 16s→~10s 目标）：check_device 的每台 2 次 DB 往返合并为批量；改完必须 bench 复测
- 引擎 _fire 通知解耦：通知发送移出评估路径（to_thread/后台 task，失败不阻塞评估）
- 根级 .dockerignore（__pycache__/.venv/dist/logs 等，加速镜像构建）
- 用户管理补禁用/改角色（第 1 期遗留）：users API + 前端；禁用用户 JWT 立即失效（看现有 token 校验最简实现）

## 验证与约定

- 测试数据 IP 段分配：203.0.113.x=ipam/logreceiver、192.0.2.9x=app_probe、192.0.2.8x=middleware；新测试用 192.0.2.7x 起
