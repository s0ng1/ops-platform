# 内网运维管理平台 · 部署手册（离线版）

适用：内网无外网 Linux 服务器，docker-compose 一键部署。

## 1. 环境要求

- Linux 服务器，已安装 Docker（≥ 20.10）与 compose 插件（`docker compose version` 能输出版本号即可）
- 服务器内存建议 ≥ 4 GB；磁盘 ≥ 20 GB（时序数据量随设备规模增长）
- 无需外网、无需安装 Python/Node，全部依赖在镜像内

## 2. 离线包结构

在有网打包机上运行 `deploy/offline-pack.sh` 产出 `ops-platform-offline-<日期>.tar.gz`，解压后：

```
ops-platform-offline-<日期>/
├── images.tar              # 三个镜像：timescaledb / ops-platform-api / ops-platform-web
├── docker-compose.yml      # 即 docker-compose.full.yml（已改名，up 时无需 -f）
├── .env.example            # 环境变量模板，复制为 .env 后修改
├── nginx.conf              # web 镜像内 nginx 配置（已打进镜像，仅供查阅/二开）
├── Dockerfile.api/.web     # 镜像构建文件（离线机一般用不到，重build才需要源码）
├── 部署手册.md             # 本文件（部署步骤速查）
├── 管理员手册.md/.docx     # 完整部署、配置、运维、安全与 FAQ
├── 用户手册.md/.docx       # 各功能模块使用说明
└── wheels/                 # Python 依赖 wheel 包（裸机部署或重建镜像时备用）
```

## 3. 部署步骤

```bash
# 1) 上传并解压
tar xzf ops-platform-offline-*.tar.gz
cd ops-platform-offline-*

# 2) 导入镜像（约几分钟，视磁盘速度）
docker load -i images.tar

# 3) 配置环境变量
cp .env.example .env
# 必改四项（未设置时 docker compose up 会直接报错拒绝启动）：
#   OPS_DB_PASSWORD     数据库密码（随机串）
#   OPS_FERNET_KEY      凭据加密密钥，生成：
#     python -c "from cryptography.fernet import Fernet;print(Fernet.generate_key().decode())"
#     （服务器无 python 可在任意有 python 的机器上生成后抄入）
#   OPS_SECRET_KEY      JWT 签名密钥（≥32 字节随机串）：
#     python -c "import secrets;print(secrets.token_hex(32))"
#   OPS_ADMIN_PASSWORD  默认管理员初始密码（首次启动创建，首登后立即改密）
# 端口冲突时改：OPS_WEB_PORT（默认 8080）
vi .env

# 4) 启动
docker compose up -d

# 5) 查看状态
docker compose ps        # db 应为 healthy，api/web 为 running
docker compose logs -f api
```

访问 `http://<服务器IP>:8080`，使用 `.env` 中 `OPS_ADMIN_USERNAME`（默认 `admin`）/ `OPS_ADMIN_PASSWORD` 设定的账号密码登录，**首次登录后立即修改密码**。

首次启动时后端自动建表（含 TimescaleDB hypertable）并播种默认管理员与内置告警规则，无需手工初始化。

## 4. 备份建议

- **数据库**：数据在命名卷 `pgdata_full`。推荐定时逻辑备份：
  ```bash
  docker exec ops-full-db pg_dump -U ops -d ops | gzip > ops-backup-$(date +%F).sql.gz
  ```
  恢复：`zcat ops-backup-*.sql.gz | docker exec -i ops-full-db psql -U ops -d ops`
- **配置文件**：`.env`（尤其 `OPS_FERNET_KEY`，丢失后已加密凭据无法解密）。

## 5. 升级流程

1. 在新离线包机器上重新运行 `offline-pack.sh` 得到新 tar.gz
2. 上传 → 解压到新目录 → `docker load -i images.tar`
3. 复用旧 `.env`（注意保留 OPS_FERNET_KEY 与 OPS_DB_PASSWORD 不变）
4. `docker compose up -d`（镜像已换新 tag 内容，compose 自动重建 api/web 容器；db 数据卷不动）
5. 表结构变更由后端启动时 `create_all` 自动补齐（新增表/列自动，删除不处理）

## 6. 常见问题

- **端口冲突**：`docker compose up` 报端口占用 → 改 `.env` 里 `OPS_WEB_PORT` 后重新 `up -d`。在 WSL2（mirrored 网络）上，Windows 宿主侧程序占用 8080 时 WSL 内 `ss` 可能看不到监听但绑定仍报 `address already in use`，同样改 `OPS_WEB_PORT` 规避（本期验证时改用 18080 通过）。
- **OPS_FERNET_KEY 变更后果**：换密钥 = 数据库里所有已加密的设备凭据（SSH/SNMP/数据库密码）全部无法解密，需重新录入。升级、迁移务必备份并沿用原密钥。
- **页面能开但实时推送不工作**：确认经过 nginx 的 80 端口访问；nginx 已配置 `/api/ws` 的 Upgrade 头。若再套一层上层反向代理，需同样放行 WebSocket。
- **数据库连不上**：`docker compose ps` 看 db 是否 healthy；密码以 `.env` 首次初始化时为准——**初始化后再改 OPS_DB_PASSWORD 不会改库里已有密码**，需 `docker compose down -v` 清卷重建（会丢数据）或用 psql 手工 ALTER USER。
- **`OPS_DB_IMAGE=postgres:16-alpine` 兜底**：拉不到 timescale 镜像时可用该镜像（体积更小，但时序压缩/连续聚合不可用）。

## 7. 服务清单

| 服务 | 容器名 | 端口 | 说明 |
|---|---|---|---|
| db  | ops-full-db  | 不对外 | TimescaleDB（pg15），数据卷 pgdata_full |
| api | ops-full-api | 不对外 | FastAPI/uvicorn，内部 8100 |
| web | ops-full-web | ${OPS_WEB_PORT:-8080} | nginx 托管前端 + /api 反代 |
