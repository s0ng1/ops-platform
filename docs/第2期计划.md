# 第 2 期 · 指标与告警 实施计划

> 2026-07-22 制定。前置：第 1 期基础骨架已完成（登录/RBAC、设备 CRUD、凭据加密、发现入库、ping/SNMP 在线监控），PostgreSQL + TimescaleDB 2.28 已实机就绪。
> 目标：设备监控从「在线/离线」升级为「指标曲线 + 阈值告警」。

## 里程碑（每个可独立验收）

### M1 时序基建 + 采集调度器（约 3 天）
- `metrics` 表：`time timestamptz / device_id / metric / labels jsonb / value double precision`
  - PG：启动时执行 DDL `create_hypertable('metrics','time', if_not_exists)` + 压缩策略（7 天后压缩）+ 保留策略（原始 30 天）+ 连续聚合（5m / 1h 降采样，报表用）
  - SQLite：退化为普通表，保证单元测试可跑；hypertable 行为仅在 PG 回归验证
- `scheduler/scheduler.py`：采集任务注册表 `{指标集: 周期}`（接口流量 1min、CPU/内存 1min、数据库 5min），asyncio 协程池分发，单设备单指标失败隔离（沿用「单点失败不阻塞整体」）
- 计数器速率通用件：内存缓存 `{(device, metric, labels): (ts, raw)}`，差值÷间隔得速率；重启后首周期跳过；处理 32/64 位计数器回绕
- 验收：手工塞一台 mock 采集源，连续跑 10 分钟，metrics 表数据连续、无任务泄漏

### M2 网络/安全设备 SNMP 指标（约 3 天）
- `collectors/snmp_metrics.py`：
  - 接口：ifHCInOctets/ifHCOutOctets（速率、带宽利用率）、ifOperStatus（up/down）
  - 设备级：CPU、内存（通用 OID 兜底 + 华为/H3C/思科私有 OID 逐步补，sysObjectID 指纹选择）
- 接口清单自动维护（ifDescr/ifAlias 变化时更新 labels）
- 验收：对真实交换机（现场联调）或 mock 数据源采集，接口速率曲线数据正确

### M3 主机指标（约 3 天）
- Windows（SNMP 主通道）：`collectors/windows.py` — HOST-RESOURCES-MIB：hrProcessorLoad（CPU）、hrMemorySize/hrStorage（内存/交换）、hrStorageTable（分区用量）、hrSWRunTable（进程数）
- Linux（SSH 主通道）：`collectors/linux_ssh.py` — asyncssh 登录执行命令集读 /proc/stat、/proc/meminfo、df；凭据用第 1 期 ssh 类型
- 验收：本机 Linux 起 sshd 实测；Windows 部分先单测 mock + 现场联调

### M4 数据库探针（约 3 天）
- `collectors/db_probe.py`：抽象 `probe(credential) -> list[metric]`
- MySQL 先行（pymysql，docker 起实例实测）：连接数、QPS/TPS、慢查询数、主从延迟
- Oracle（v$ 视图）/ SQLServer（DMV）留好抽象与 SQL 清单，按现场数据库种类与只读账号落实情况补
- 验收：docker MySQL 实测指标入库

### M5 告警引擎 + 通知（约 3 天）
- 模型：`alert_rules`（名称、指标、比较符、阈值、持续周期数、等级 critical/major/warning/info、设备选择器 type/group/device、通知渠道、启用开关）
- `alert_events`：firing → resolved 状态机，连续 N 周期越限触发（去抖），恢复同理；确认（ack）/关闭流程
- `alerting/engine.py`：每轮采集后对相关规则求值；设备离线、接口 down 作为内置规则
- `alerting/notify.py`：SMTP 邮件、钉钉/企业微信机器人 Webhook；通知失败静默记日志不阻塞
- 验收：构造越限数据，告警触发→通知（webhook 用 mock 服务）→恢复→关闭全流程

### M6 前端：曲线 + 告警中心 + WS（约 3 天）
- 设备详情页：ECharts 曲线（接口流量/CPU/内存 tab，时间范围选择），最新指标卡片
- 告警中心：未恢复告警列表（等级色块）、确认/关闭、历史检索；规则管理页
- 顶栏：按等级未恢复告警计数（北塔截图样式：致命/严重/警告/信息 红橙黄蓝色块），点击跳告警中心
- WS `/api/ws`：进程内广播器（`core/broadcast.py`）推送设备状态变化与新告警，仪表盘/顶栏实时刷新；不引 Redis
- 验收：浏览器全流程操作，WS 断开自动重连

## API 新增清单

- `GET /api/devices/{id}/metrics?metric=&from=&to=&agg=` 曲线数据（raw/5m/1h）
- `GET /api/devices/{id}/metrics/latest` 最新值快照
- `GET /api/metrics/catalog` 设备已采集指标清单
- CRUD `/api/alert/rules`
- `GET /api/alert/events?status=&severity=`，`POST /api/alert/events/{id}/ack`、`/resolve`
- `GET/PUT /api/notify/settings` 通知渠道配置（SMTP 密码等敏感字段 Fernet 加密）
- `WS /api/ws`

## 依赖新增（内网离线打包清单同步更新）

- 后端：`asyncssh`（Linux SSH）、`pymysql`（MySQL 探针）
- 前端：`echarts`
- 可选后补：`oracledb`、`pymssql`（按现场数据库种类定）

## 测试策略

- 采集器：mock pysnmp/asyncssh/pymysql 响应的单元测试；速率差值与计数器回绕专项用例
- 告警引擎：阈值/去抖/恢复/ack 状态机用例
- API：沿用 SQLite（默认）/ PG（`OPS_TEST_DATABASE_URL`）双跑；hypertable DDL 仅 PG 验证
- 联调：MySQL 用 docker 实测；SNMP/Windows/Oracle 等现场联调

## 风险与对策

- **无真实 SNMP 设备**：开发期全靠 mock；M2/M3 的 OID 适配留到现场联调，指纹库先覆盖华为/H3C/思科主流
- **数据库探针范围**：现场库种类未最终确认，先交付 MySQL，其余按抽象快速补
- **TimescaleDB 镜像依赖代理拉取**：已解决（本地已有镜像；离线交付时需 `docker save` 打包）

## 明确不做（本期）

- 拓扑图（第 3 期）、报表导出/大屏（第 4 期）、Redis、多进程 worker
- 磁盘 IO（Windows 标准 SNMP 盲区，WMI 补充通道按现场条件再定）
