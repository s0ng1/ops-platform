# 第 7 期计划 · 监控对象扩展（Oracle/SQLServer 探针 / 应用拨测 / 中间件两件套）

> 2026-07-27 定稿。接第 6 期（网络运维周边），继续对标北塔补覆盖面。
> 北塔数据库 17 种、标准应用 12 种、中间件 19 种；本期补性价比最高的部分，JMX 类与国产库留扩展点。

## M1 Oracle / SQLServer 探针

- `collectors/db_probe.py` 的 db_type 分发点补 `oracle` / `sqlserver` 两个分支（MySQL 探针模式照搬：同步驱动 + asyncio.to_thread + rate.py 累计计数器差值）
- 新依赖：**oracledb**（thin 模式纯 Python，无 Instant Client）、**pytds**（纯 Python；pymssql 有 C 扩展不引）——加进 requirements 并验证 pip download 可离线
- 指标对齐 MySQL 粒度：
  - Oracle：会话数（v$session）/ 表空间使用率（dba_tablespaces+dba_data_files）/ 慢 SQL 计数（v$session_longops 或 v$sql 耗时Top，按可得性定）/ 实例可用性+响应时间
  - SQLServer：连接数（sys.dm_exec_connections）/ 缓存命中率（sys.dm_os_performance_counters Buffer cache hit ratio）/ 批请求速率（Batch Requests/sec 累计差值）
- 凭据：复用现有 database 类型凭据（host/port/库名或服务名/user/password），db_type 字段区分
- 实测：docker 起 gvenzl/oracle-xe:18-slim 与 mcr.microsoft.com/mssql/server:2019-latest（拉镜像走代理 127.0.0.1:7897；SQLServer 需 ACCEPT_EULA）；建只读监控账号，实测两轮采集入库（瞬时+速率全出）。镜像拉不动就 mock 单测 + 留真库联调欠账记录
- 内置规则按需补（表空间使用率 >85% 等，照 MySQL 连接使用率模式）

## M2 应用仿真拨测

- 新设备类型 `application`（target 配置存 device 的 JSON 字段或复用现有字段，看现状最小改动）+ `collectors/app_probe.py`（纯 asyncio，零新依赖）：
  - http/https：URL + 期望状态码 + 响应关键字（可空）+ 超时；指标 app_available / app_latency / app_status_code
  - dns：域名 + 期望解析结果（可空）；app_available / app_latency
  - tcp：host:port 连通性（+banner 匹配可选）；app_available / app_latency
- 注册 TASKS 60s；内置规则「应用不可达」
- 前端：设备表单按 type=application 显示拨测配置表单项；设备详情 catalog 加应用组曲线
- 测试：本地起 http.server / UDP DNS 假响应 / TCP echo 做真拨测单测

## M3 中间件轻量两件套（Nginx / Redis）

- Nginx：stub_status 页 HTTP 抓取（active/reading/writing/waiting/accepts/handled/requests，速率类走 rate.py）
- Redis：TCP 直连发 INFO（RESP 协议手撸解析，零依赖）：connected_clients/used_memory/used_memory_rss/keyspace_hits+misses→命中率/ops_per_sec（instantaneous）
- 作为 application 的子类型（probe_kind=nginx|redis）还是独立 type——实施时按代码现状选侵入小的，写进进度记录
- 实测：docker 起 nginx（开 stub_status）与 redis 容器验证；拉不动就 fixture 文本单测
